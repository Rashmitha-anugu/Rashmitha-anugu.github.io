What it catches

BreakMeaning
MISSING_SETTLEMENTThe ledger captured it, the processor never settled it
AMOUNT_MISMATCHSettled for a different amount
DUPLICATE_SETTLEMENTSettled more than once
ORPHAN_SETTLEMENTThe processor settled something the ledger never saw
STATUS_MISMATCHThe ledger says failed, the processor settled it
AWAITING_SETTLEMENTCaptured today; the T+1 file isn't due yet

Design decisions

  • Ordered by log sequence number. Postgres LSN is the only ordering guaranteed to match commit order; timestamps and arrival times aren't.
  • Idempotent merges. An incoming row merges only if its LSN is newer, so late or replayed files can never roll a transaction backwards.
  • At-least-once, everywhere. Every model deduplicates on key and LSN, which trades exactly-once for one-minute freshness without risk.
  • Deletes kept for audit. Hard deletes become soft deletes with the full row preserved; batch extracts would miss them entirely.
  • A contract on the finance model. Changing the reconciliation table's columns fails the build instead of quietly breaking reports.
  • Least privilege. Terraform provisions write-only and read-only roles and a key-pair-only service user.
